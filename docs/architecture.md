# NexusSklad Architecture

Дата: 1 марта 2026
Статус: draft

## 1. Общая архитектура

Проект строится как multi-app продукт:

- `mobile app`
- `web app`
- `api`
- `shared package`

## 2. Компоненты

### Mobile

Технология:

- `Flutter`

Задачи:

- приемка;
- расход;
- инвентаризация;
- просмотр остатков;
- работа владельца с телефона.

### Web

Технология:

- `React + TypeScript + Vite`

Задачи:

- отчеты;
- управление пользователями;
- расширенный просмотр данных;
- удобная работа владельца с ноутбука.

### API

Технология:

- `Node.js`
- `TypeScript`
- `Fastify`
- `Prisma`
- `PostgreSQL`

Задачи:

- авторизация;
- CRUD товаров и категорий;
- движения склада;
- инвентаризация;
- аудит;
- отчеты.

## 3. Архитектурные принципы

1. Mobile-first.
2. Простая доменная модель на старте.
3. Транзакционность операций изменения остатка.
4. Лог аудита на каждое важное действие.
5. Возможность offline-first эволюции.

## 4. Модули backend

- `auth`
- `users`
- `companies`
- `categories`
- `products`
- `movements`
- `inventory`
- `reports`
- `audit`

## 5. Важные архитектурные решения

1. Остаток хранится явно в товаре и пересчитывается через validated movements.
2. Каждое движение сохраняет `beforeQty` и `afterQty`.
3. Инвентаризация хранится как отдельная сущность, а не как набор ad-hoc корректировок.
4. Роли минимальные: `owner`, `manager`, `staff`.
5. На старте нет тяжелых интеграций.
